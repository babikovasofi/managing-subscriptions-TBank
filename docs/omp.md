# Работа в Oh My Pi

## Запуск

В обычном профиле OMP 19.1.1 авторизуй OpenAI один раз через `omp login openai-codex`.
Перед запуском передай `DEEPSEEK_API_KEY` через окружение из своего хранилища
секретов. Из корня репозитория:

```sh
omp --config .agents/omp.yml
```

Чтобы продолжить последнюю сессию, добавь `--continue`. Обычный профиль OMP
использует существующий вход. Файл `.agents/omp.yml` задаёт маршрутизацию
для этого запуска. GPT-6.2 Sol и уровень `medium` уже заданы в этом файле.
Если в твоём zsh настроен автоматический выбор этого конфига для папки
проекта, достаточно `omp` или `omp --continue`.

В OMP используй `/skill:plan`, `/skill:build`, `/skill:review`, `/skill:debug`.
В standalone Codex используй `$plan`, `$build`, `$review`, `$debug`. В Claude Code
используй `/plan`, `/build`, `/review`, `/debug`. Все три клиента используют
`.agents/skills` как источник общего процесса.

## Распределение работы

- **Codex** ведёт сессию, готовит и согласовывает план, решает вопросы требований,
  дизайна, API и диагностики. Для консилиума и ревью запускает отдельные сессии
  на полном селекторе `openai-codex/gpt-6.2-sol:medium` из `modelRoles.default` через `agent: task`. При ревью
  ставит `isolated: true` и отбрасывает любой патч. Каждому сабагенту передаёт
  инструкции роли из `.claude/agents` и исходные данные задачи.
- **DeepSeek** получает поручения с известным способом выполнения. Примеры
  включают замены по заданной таблице, перенос по образцу и повторение уже
  утверждённой правки в аналогичных файлах. Пакет содержит разрешённые пути,
  точное правило, эталон и ожидаемый результат. Для нескольких параллельных
  поручений пути правок не пересекаются. Используй `agent: sonic`, точный
  селектор из `modelRoles.mechanical`, `isolated: true` и краткий `solutionSpace`.
- В каждый элемент вызова `task` явно передавай `model` с полным ID из
  конфигурации. Для такого вызова OMP возвращает ошибку при недоступности модели
  или авторизации. Не повторяй вызов с другим селектором или без него.
- OMP сохраняет изолированную работу как патч без автоматического применения.
  Codex берёт путь из результата изолированной задачи (`patchPath`), проверяет
  пути и содержание патча, применяет принятые изменения после `git apply --check`
  и запускает проверки из плана на собранном diff.
  При конфликте или выходе за поручение верни правку на доработку.
- Финальный ревьюер Codex получает утверждённый план, итоговый diff и фактические
  результаты проверок. Коммит и пуш требуют согласия пользователя.
